# Infigo Hacks — Roadmap

Living hub for documenting and solving gaps in the Infigo storefront platform that Infigo itself hasn't addressed.

## Now
- **New-storefront build (in progress, Nov 2026).** Two account-prefilled MegaEdit products are live and verified from site PDFs, both built with the MexGen builder: a three-layout business card and a one-layout rep magnet. Bulk product work runs through the Excel import (`docs-library/01-official-infigo/product-excel-bulk-import.md`). Remaining: static PDF products from supplied artwork, and publishing the placeholder products. Customer detail lives outside this repo.
- **Multi-location business card redesign: v3 import-verified 2026-11-18 and sent to the customer.** A five-location dropdown product was re-skinned onto the customer's new art by patching the v1 MEX in place (same ids, variables and logic rules), so the dropdown still swaps the art, colors and address. The customer's PDFs came without bleed; a mirrored edge raster under the vector art supplies it. v2's import showed MegaEdit's single-line text model, which ignores font metrics: baseline = frame top + 0.95 × size at 120 % leading (in general `(leading% − 0.25) × size`), and frames shorter than 1.3 × size get their type shrunk. v3 put every baseline at 0.00 pt error. Now in `MexGen Agent/SPEC.md` §5. Customer detail lives outside this repo.
- **Coupon card with editable offer lines — v-01 printed wrong, fixed 2026-11-18.** 2-sided 8.5x3.5, back has three customer-editable lines (amount, expiry, store info) over a background with those text runs redacted (PyMuPDF text-only redaction, images and vectors kept). The first live order printed the big script-font amount 36 pt low, over the line below it: v-01 sized frames from the font's hhea metrics, but MegaEdit places a single line at `frame top + (leading% − 0.25) × size` regardless of font (the 0.95 rule is this at 120 %). The order PDF was patched and printed correctly; v-02 is rebuilt on the general rule and awaits import. `MexGen Agent/SPEC.md` §5. Customer detail lives outside this repo.
- **Three-version postcard in one MegaEdit product — built 2026-11-16, awaiting customer review.** A dropdown picks one of three art versions (two mailers and a contact card), with a shared address block and per-version contact fields. First generated `logicRules[]` Show/Hide rule (if / else-if / default) and parent-linked form inputs, no Invent in the loop. `validate --strict` clean, not import-tested. Write-up: `docs-library/04-megaedit/two-version-dropdown-show-hide-generated.md`. Customer detail lives outside this repo.
- **Product-attribute values via the REST API — Infigo ticket open (2026-10-01).** `orderlineitem/get` returns the right line but `ProductAttributes: []` for a Static (type 30), PrintIQ-quoted product whose dropdown attribute shows in the Order Line Detail report. That contradicts the spec. Checkout attributes don't fit (the codes are per-product, and the store has many departments). Fallbacks while waiting: parse the job-ticket PDF, or map the orderline `Attributes` placeholder into a PrintIQ Additional Reference Field (POD only). Write-up: `docs-library/01-official-infigo/api-order-line-attributes.md`.
- **QR business card, CSV batch — PASSED on the sixth import (2026-09-28).** Five-row batch on the storefront: every QR decodes to its own row, navy, text at 0.00 pt from the approved PDF. Six imports produced eight verified MEX facts, all in `docs-library/07-invent/mex-file-format-anatomy.md` and the generator's SPEC: trim-origin coordinates, batch as four in-file switches, the `Barcode Field` script, variable-bound barcodes, the XML colour carrier, exports never carrying editor changes. ## Next
- **Location data outside the MegaEdit template (researched 2026-09-28, deferred).** Multi-location business cards bake every address and phone number into the template, and replacing a template breaks reorders, so each small data edit costs a full product revision (copy → rename → hide old but keep orderable; one product is on its thirteenth). Candidate fix: one last revision where Address/Main/Fax are plain text variables, filled by an Editor script that looks the chosen location up in an admin-managed Custom Data Category (`types-for-megaedit` `EditorData` + `Invent.Variables.Set`). Blocked on: Infigo confirming the Custom Data Category admin screen, and a throwaway-product test that attaching a script doesn't break reorders. Watch the batch caveat in Closed below (`Variables.Set` in CSV batch). **New lead (2026-10-01):** the March 2026 release added a native route. An Invent Text Library can use **External Data Source = Custom Data** (Category Id / Key Field / Value Field), and MegaEdit fills the dropdown from Admin → Custom Data at load, with no script. This may replace the editor-script plan. Infigo Support enables Custom Data access per role. Test reorder behaviour and several values per key first. See `docs-library/07-invent/invent-centrally-managed-dropdowns.md`.
- Build the split-CSV + two-template workflow as a reusable pattern in `docs-library/` for the **non-image-swap** subset of the Variable Logic gap (multi-field show/hide from CSV still needs split-CSV).

## Operating principles
- Verify behavior empirically against actual cart/storefront — Infigo docs are thin.
- Grep `docs-library/` BEFORE web searching.
- Bypass PrintIQ live pricing for batch products — use custom Infigo pricing scripts.
- Build reusable generators, not one-off fixes.
- When working in editor scripts: pick the right NPM package (`types-for-megaedit` for browser, `types-for-megascript` for server) and the right ExecutionType on Admin → MegaEdit Product Scripts.
- Don't ticket Infigo for non-bugs they'd quote a custom script for — the cost-benefit rarely works for our project sizes.

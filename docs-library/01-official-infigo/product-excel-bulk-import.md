# Product bulk import via Excel — verified behavior (live storefront build, 2026-11-03)

## Problem
Need to create dozens of products (with categories) at once from a customer product list, before all artwork exists.

## Root cause / how the tool actually works
- Catalogue > Products > Product Management > Export to Excel = the template (89 cols). Always export fresh; headers change.
- ProductId blank = create. ProductId present = update that product (dialog says so; Academy p/1685 says import can't update — dialog is newer, trust the dialog).
- CategoryIds = numeric category IDs (get them from Categories > Export XML `<Id>`), NOT names.
- ProductType exact strings: `StaticPDF`, `Stock`. ProductTemplateId: StaticPDF=0, Stock=1 (copy from a real exported row of each type).
- No ConnectID column in the export, even though the dialog says Connect Configurations are importable.
- Extra columns you add yourself: ProductAsset (PDF / .mex filename in Upload Location), ProductImage (pipe-separated, replaces existing), ProductAttributes (semicolon-separated, attributes must pre-exist).

## Fix / workflow
1. Create categories by hand, export categories XML for IDs.
2. Hand-make one product of each type, export -> template + exact type strings.
3. Build sheet: ProductId blank, Name, SKU (= PrintIQ job #), CategoryIds, ProductType, ProductTemplateId, Published=False.
4. Import with Upload location = None if no assets yet.
5. Re-export -> ProductIds. Later batches = update rows by ProductId + ProductAsset + Upload location.

## Sample
One new storefront: 46 products (13 StaticPDF, 33 Stock) imported in 2 passes with zero errors. The import sheet was generated by a small local script from the customer product list.

## Caveats
- **StaticPDF imports fine with NO ProductAsset** (verified) — create placeholders now, attach PDFs later.
- Re-importing a row without ProductId creates a duplicate — strip already-imported rows.
- Uploaded assets are deleted from the Upload Folder after import.
- **Category change on update works and replaces** [LIVE, Nov 2026]: re-importing an exported row with its ProductId kept and a different single CategoryIds value moved the product; a fresh export showed only the new category, not both.
- **An update row overwrites every column**, so always build update sheets from a fresh export. A sheet built from an older export puts back whatever has changed on the site since (names, categories, published state). Include only the rows you mean to change.
- Round-tripping an export through a script turns empty-string cells into empty cells; the import accepts that. [LIVE, Nov 2026]
- Not yet verified: attaching ProductAsset on an update-by-ProductId row; changing ProductType on update; multi-category separator.
